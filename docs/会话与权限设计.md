## 2. 会话模型（FastAPI 阶段实现）

- 表 `user_sessions(user_id, token_hash, created_at, last_seen_at, revoked_at)`；
- 登录 → 生成随机 token，**库中只存 sha256**，明文仅回客户端；
- 注销 → 删除/标记该行；管理员"吊销会话/停用/改角色/转让" → 批量删该用户会话（强制重新登录）；
- 生命周期固定（不过期、不滑动刷新），默认不强制空闲过期，管理员可随时吊销；
- 客户端不得把 token 落明文日志/明文文件（存系统凭据库或本地加密）。

## 3. 最高管理员（admin）不变量与操作

- **至多一个 `role_type='admin'`**：数据库级部分唯一索引
  `uq_sys_users_single_admin ON sys_users (user_id) WHERE role_type='admin'`（已加进 init_db.sql）；
- **首个注册=admin**：`register_user` 先查"是否存在 admin"，无则本次以 admin 创建；
  并发竞态（两人同时通过检查）→ 唯一索引只放行一个，失败者自动降级为普通角色重试一次；
- **转让**（单事务原子）：目标 → admin；旧主降级（默认 financial_role）；
  删旧主全部会话 → 旧主前端强制回登录框；
- **不可**：admin 注销/停用自己而不先转让（服务端强制校验）；
- **注销账户 = 软停用**（保留审计/台账痕迹），非删行。

## 4. 角色语义（沿用现有 role_type）

| role_type | 语义 | 权限 |
|---|---|---|
| `admin` | 最高管理员（唯一） | 管人：停用/启用/吊销会话/转让/审计查看 + 业务全权限 |
| `financial_role` | 业务最高权限（可多名） | 字段调整/台账状态/敏感解密（即现行 f_r） |
| `finance_staff` | 普通只读 | field:read |

（现 seed 中 financial_role 与 admin 权限完全相同——按上述语义，后续把"管人"权限点只授给 admin，业务权限仍授两者。）

## 5. UI 要求（桌面端，FastAPI 前后一致）

## 6. 审计（制衡 admin 的"可销毁一切会话"权力）

`sys_audit_log`：登录/注销/吊销/停用/转让/改角色/敏感解密，记录 谁、何时、做了什么。

## 8. RAG/关联/规则 三层架构（对应 AI 对话框与"新 AI 接入 RAG"）

纯 RAG（召回+按上下文生成）不满足财务"核对/关联"需求。采用三层，**LLM 不判定钱**：

1. **检索层 = RAG**（现有 pgvector）：语义召回候选段落；
2. **关联层 = 文档节点 + 类型化边**（不用图数据库，关系表即可）：
   边由确定性规则从现有产物生成：同合同编号 / 同实体编码 CO·PT / 同项目哈希 /
   日期时序 / 金额与四流特征；
3. **规则引擎 = 核对层**：金额一致、编号匹配、日期先后、收款/开票状态 vs 凭证，
   代码规则判定（确定性、可审计），产出命中/未命中清单；
4. LLM 只做综合证据 + 解释规则结果 + 处理例外，答案附**证据链**
   （关联文件列表 + 规则判定点 + RAG 段落并集）。
